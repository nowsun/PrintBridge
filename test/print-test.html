PrintBridge 打印服务测试页

用于在虚拟机中测试 ① 网站白名单 与 ② Office 文件打印。所有请求都发往本机运行的 PrintBridge。

⚠️ 使用前必读：白名单怎么起作用的

PrintBridge 会校验每个打印请求的 Origin 请求头，只有命中「白名单」才受理，否则返回 403 Origin not allowed。浏览器会自动带上本页面的 Origin，无法手动伪造，所以：

  • 本页必须从一个「白名单内的源」打开才会被放行；直接双击以 file:// 打开，Origin 是 null，会被拒绝。
  • 默认白名单：https://siksoft.com（含子域名 https://*.siksoft.com）、http://localhost:8080、http://127.0.0.1:8080。
  • 推荐在 8080 端口起一个静态服务器，把本目录（含测试用 Office 文件）作为根目录：
# 在本目录(test/)下，任选其一：
python -m http.server 8080
npx http-server . -p 8080
# 然后浏览器打开： http://localhost:8080/print-test.html

这样页面 Origin 是 http://localhost:8080（命中白名单），同时 Office 测试文件也能以 http://localhost:8080/xxx.docx 形式被 PrintBridge 下载。

服务器连接

「白名单状态」由页面向服务器发真实请求判定（不依赖页面内置列表，与 app 里 printbridge.ini 的实际配置一致）。健康检查(GET /health)不做 Origin 校验，可用来确认连通性。

一、网站白名单测试

点击「测试白名单」会向 POST /print 发一个空请求体（不会真正打印）。 结果含义：400 = Origin 在白名单、请求已受理（空体所以报 400，属预期）； 403 或「浏览器 CORS 拦截」 = Origin 不在白名单、被拒绝。

「模拟非白名单源」使用 mode:'no-cors' 走一条不携带 CORS 凭据的通道，配合控制台(F12)可观察服务器返回 403。 更可靠的对照方法是换一个端口（如 3000）起服务器再打开本页，即可看到真实被拒效果。

命令行对照测试（在 PowerShell 里，可精确指定任意 Origin）：

# 白名单内 —— 预期 HTTP 200（请求体为空会返回 400，但说明 Origin 已放行）
curl.exe -X POST http://127.0.0.1:8281/print -H "Origin: https://siksoft.com" -H "Content-Type: application/json" -d "[]"

# 白名单外 —— 预期 HTTP 403 Origin not allowed
curl.exe -X POST http://127.0.0.1:8281/print -H "Origin: https://evil.com" -H "Content-Type: application/json" -d "[]"
